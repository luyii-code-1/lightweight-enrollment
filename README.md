# Lightweight Enrollment · 轻量报名系统

面向资源有限服务器的校园社团报名系统。单进程 Node.js API、React 前端和 PostgreSQL，使用 Docker Compose 部署，无需 Redis。

## 功能

- 高一、高二独立课程名额；学生每人一门课程，支持报名、退选、释放名额。
- 2 秒一批的持久化报名队列，事务和唯一约束防止超卖与重复报名。
- 随机 Cookie 会话，有效期 2 小时；新登录撤销旧会话。
- 管理员管理学生、密码、权限、课程容量、报名时间和 CSV 导出。
- 手动刷新、会话限流、请求重试、两位数加法验证、课程海报弹窗。
- 用户 ID 水印，GMT+8 时间与时差提示；偏差提示不阻止报名。

## 快速启动

需要 Docker 和 Compose。复制 `.env.example` 为 `.env`，填写随机数据库密码、至少 32 字符 Cookie 密钥和管理员密码。数据库密码使用字母数字，避免连接字符串转义问题。

```sh
cp .env.example .env
# 编辑 .env 后启动
docker compose up -d --build
```

打开 `http://localhost:6754`。管理员使用 `.env` 中的用户名、密码；配置 `ADMIN_TOTP_SECRET` 后还需输入验证器验证码。TOTP 密钥为 32 字符 Base32，SHA-1 / 6 位 / 30 秒。管理员配置只用于首次建号，不覆盖已存在的账号。

默认端口仅绑定本机。公网部署必须配置 HTTPS 反向代理、`COOKIE_SECURE=true`、精确的 `ALLOWED_ORIGINS`，并将 `TRUSTED_PROXIES` 设为实际代理地址。禁止直接开放数据库端口。

## 数据导入

后台导入 CSV，模板见 `examples/`。示例账号为虚构测试标识，不对应真实学生。导入学生支持身份证号、姓名、年级、班级、初始密码；密码省略时使用账号后六位。年级当前支持 1、2。1–4 班默认限制报名，可在后台调整。

课程 CSV 包含课程编号、课程名称、年级、教师、地点、容量、说明。学生只显示本年级课程。海报放置于 `apps/web/public/posters/课程名称.jpg`，在构建时打包；不要提交未经授权的海报或学生名单。

## 运行与资源

默认应用上限 256 MB、数据库 768 MB，数据库连接池 16。建议至少 2 核 / 2 GB 内存，并为操作系统与代理留出余量。数据库磁盘延迟会直接影响登录、改密、报名提交；内存队列不能代替持久化事务。

应用保持单进程，验证码与限流状态保存在内存，报名队列和会话保存在数据库。不要直接增加应用副本；横向扩容需要先共享验证码与限流状态。本项目未承诺持续 600 请求/秒，需在目标硬件上单独压测。

```sh
docker compose logs --tail=100 app
docker compose stop
```

停止会保留数据库卷。升级前备份 PostgreSQL，不要使用 `docker compose down -v` 清除正式数据。

## 开发与测试

需要 Node.js 22+ 和 PostgreSQL 17。宿主机开发时将 `DATABASE_URL` 改为可访问的数据库地址。

```sh
npm ci
npm run dev
npm run build
npm test
```

前端开发端口 5173，API 6754。当前测试为协议、限流、安全响应、TOTP 等单元测试，不等于生产容量验收。

## 安全与适用范围

- 身份证账号与后六位初始密码是兼容原报名流程的设计，不适合面向公众的高安全身份认证。部署方应最小化采集、限制管理员范围并设定数据保留期限。
- 身份信息找回密码接口保留在源码中，公开版本默认禁用；姓名、班级和身份证不是秘密，不能独立证明身份。管理员可直接重置学生密码。
- Base64 是编码，CRC32 只能检错，不是加密或签名。客户端时间可以伪造；队列按批次处理，无法保证跨设备绝对时间公平，后到请求不会挤出已确认报名。
- API 不应使用共享缓存；只缓存静态资源。生产凭据、备份、日志和报名导出不要提交到 Git。
- 原站点专用代理、遥测配置、运维脚本和数据库资料未包含在这个发行版中。
